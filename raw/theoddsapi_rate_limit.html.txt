When a request is rate limited, the API returns a 429 error code.</p> <p>The current rate limit is 30 requests per second on paid usage plans. Even if you send requests below the rate limit, you might still encounter 429 errors sometimes. There are a couple of reasons for this:</p> <ul><li><p>If our system receives a large increase in traffic, it will take some time to scale up, usually in the order of minutes. While this is happening, some requests might be knocked back with 429s.</p></li> <li><p>If requests are sent at a rate close to the limit, some requests can still trigger rate limiting since our servers can receive requests at a different rate to which they are sent. For example, if you send 30 requests per second for 2 seconds, our servers might receive 25 requests in the first second, 33 in the next second (3 of which will be limited), and the remaining 2 requests after that. The rate at which our systems receive the requests will depend on network conditions, which are influenced by many factors outside of our control.</p></li></ul> <p>Both of these scenarios mean that 429s can occur sometimes, and they are more likely if requests are being sent close to the limit.</p> <p>To handle a request that has been rate limited, consider retrying the request after a couple of seconds. Also avoid unnecessary API calls. For example, API calls to the sports or events endpoints can be made infrequently, since the responses don't change often.</p> <h2 id="reduce-the-likelihood-of-429s"><a href="#reduce-the-likelihood-of-429s" class="header-anchor">#</a> Reduce the likelihood of 429s</h2> <ol><li>It is highly recommended to combine multiple markets in the same request if you are not already doing so. Markets can be combined with a comma separator.</li></ol> <div class="language- extra-class"><pre class="language-text"><code>❌ If you need multiple markets, don't send one request per market

https://api.the-odds-api.com/v4/sports/americanfootball_nfl/odds?markets=h2h

https://api.the-odds-api.com/v4/sports/americanfootball_nfl/odds?markets=spreads

</code></pre></div><div class="language- extra-class"><pre class="language-text"><code>✅ Instead, combine markets into a single request using comma separators in the markets parameter

https://api.the-odds-api.com/v4/sports/americanfootball_nfl/odds?markets=h2h,spreads

</code></pre></div><p>The same applies if you are querying multiple regions.</p> <ol start="2"><li><p>Reduce calls to endpoints that don't update frequently, such as <code>/sports</code> or <code>/events</code> endpoints. This can be done by caching the responses. The cache duration will depend on the needs of your application. For example, you might cache the <code>/sports</code> response for an hour, and the <code>/events</code> endpoint for 10 minutes.</p></li> <li><p>If an endpoint returns empty results (for example, immediately after a round of games, or if the sport is out of season), send requests less frequently until games become available again.</p></li></ol> <h2 id="summary"><a href="#summary" class="header-anchor">#</a> Summary</h2> <ul><li>Send requests below the rate limit</li> <li>Expect 429s sometimes, especially if sending requests close to the rate limit. When a 429 is encountered, retry the request after a couple of seconds. If possible, space requests out over a longer time period rather than sending many requests in short bursts.</li> <li>If you are querying multiple markets, ensure markets are combined into a single request rather than sending one request per market. The same applies to regions.</li> <li>Send less frequent requests to endpoints that don't update frequently, such as the <code>/sports</code> and <code>/events</code> endpoints. Save or cache the response for use in between requests.</li> <li>Send less frequent requests to endpoints that aren't returning any data</li></ul> <div class="footer" data-v-f4546cee><div class="links" data-v-f4546cee><a href="https://twitter.com/The_Odds_API" data-v-f4546cee>
