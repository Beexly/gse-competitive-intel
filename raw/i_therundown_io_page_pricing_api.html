What is a data point?

For odds, one data point is one returned price row: participant or outcome × line or value × affiliate/data source. V2 event snapshot responses also bill event, score, and live-state rows; the response headers are authoritative.

Frequently Asked API Questions

Common Questions

Sign up for the Free plan — no credit card required. You get 20,000 data points per UTC day, up to 200,000 per UTC calendar month, access to 3 sportsbooks, and pre-match odds immediately. When you need more, upgrade to Starter ($49/mo) for currently published paid-tier data sources and live data, or Pro ($149/mo) for a 30-second data delay. See all plans.
Every plan includes adjustable soft and hard limits so you stay in control. Set a soft limit to get a warning notification and a hard limit to cap usage automatically.

On the Free plan, you have a 20,000-point UTC daily cap and a 200,000-point UTC calendar-month cap. Requests return a 429 status when either is reached. No surprise charges.

Monthly and annual self-serve plans (Starter through Max) start hard-capped: automatic overage is off unless you explicitly enable it in Spend Controls. Enabling it without a saved dollar limit creates an initial cap equal to one subscription-period price; you can edit it in Spend Controls. New weekly subscriptions start with automatic metered overage enabled at the listed plan rate; without a saved limit, their editable fallback is 3× the weekly price. In block mode, requests return 429 at the hard cap. Monthly/annual rates per million data points are Starter $12.25, Pro $7.45, Ultra $4.99, Super $3.25, Mega $2.50, and Max $1.25; weekly rates retain the plan's 20% flexibility premium. Paid plans can also buy one current-plan refill at their cadence's bundled unit rate; prepaid data points are used before overage, survive allowance resets, and expire after 12 months. Enterprise plans have custom limits. Contact us for details.
Currently published sources include:

Sportsbooks: Pinnacle, HardRock, theScore Bet, FanDuel, BetMGM, DraftKings, Unibet, Bodog, Bovada, Matchbook, BetOnline, LowVig, SportsBetting, Intertops, YouWager, BookMaker, BetCRIS, Circa Sports, Heritage Sports, and Bet105
Exchange-model sources: Kalshi, Polymarket, Polymarket US, Novig, and ProphetX

Availability varies by source, sport, and market. Check the /api/v2/affiliates endpoint for the currently published roster and IDs. Published operators use the same event/markets/lines/prices hierarchy for sportsbook and prediction-market prices.
One odds data point is one returned price row: participant or outcome × line or value × sportsbook. Missing prices are not charged. Additional participants, alternate lines, and sportsbooks each add returned rows. Examples:

• GET /api/v2/events/{id}?market_ids=1&affiliate_ids=3&main_line=true&hide_closed=true — a two-sided moneyline normally returns two participant price rows = 2 odds data points, plus the response's event/score/live-state rows
• GET /api/v2/events/{id}?market_ids=1,2,3&affiliate_ids=3,19,23&main_line=true&hide_closed=true — six main-line participant/outcome rows × three books = up to 18 odds data points when every price is available, plus event/score/live-state rows

Every successful 200 snapshot bills the price rows it returns, even when a price is unchanged. V2 event snapshot responses also add one event datapoint per event, one score datapoint when present, and one more score-category datapoint when live game state is present. Delayed plans should repeat narrow filtered snapshots at the cadence their use case needs. On a zero-delay plan, use /api/v2/markets/delta only when the account has a known zero-delay entitlement, the bootstrap response explicitly returns X-Data-Delay-Seconds: 0, and meta.delta_last_id is a valid positive integer (as a number or numeric string). Otherwise, repeat a narrow filtered snapshot. Each changed price row is one odds point. X-Datapoints is authoritative for the billed total on billed responses. X-Datapoints-Breakdown is optional, is not currently emitted by /api/v2/markets/delta. WebSocket price-row messages count as one point each. Reference data (/sports, /affiliates, and /markets) is always free.
Ultra+ plans can connect a server to wss://therundown.io/api/v2/ws. Authenticate with an X-TheRundown-Key header sourced from your environment.

Subscribe explicitly to markets, scores, plays, or live. Request snapshot: true in the subscription parameters, bounded by event_ids or sport_ids plus date; the plays channel requires event_ids.

The stream sends snapshot frames, then snapshot_complete, then deltas. An existing subscription can request a fresh snapshot with action: snapshot.

The dedicated /ws/markets endpoint is for odds updates only. Filter it by market_ids, affiliate_ids, and event_ids; each market_price frame carries one changed price row. Keep a REST baseline and use it for recovery. Read the multiplexed WebSocket guide.
