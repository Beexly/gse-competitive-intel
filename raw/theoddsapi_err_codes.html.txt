If you encounter an error that is not documented on this page, it can be reported to <a href="mailto:team@the-odds-api.com">team@the-odds-api.com</a>. Be sure to include the full API URL that caused the error.</p> <p>Errors can depend on the specific endpoint being called. For details on specific endpoints and example API requests, see <a href="/liveapi/guides/v4/" class="router-link-active">the docs</a>.</p> <h2 id="missing-key"><a href="#missing-key" class="header-anchor">#</a> MISSING_KEY</h2> <p>An <code>apiKey</code> query parameter is required for all calls to the API, for example</p> <p><code>https://api.the-odds-api.com/v4/sports?apiKey=YOUR_API_KEY</code></p> <h2 id="invalid-key"><a href="#invalid-key" class="header-anchor">#</a> INVALID_KEY</h2> <p>The API key was invalid or not associated with a subscription.</p> <p>For sample URLs, the API key is commonly <code>YOUR_API_KEY</code> or <code>{apiKey}</code>, in which case it will need to be replaced with a valid API key associated with <a href="/#get-access">a subscription</a>.</p> <h2 id="deactivated-key"><a href="#deactivated-key" class="header-anchor">#</a> DEACTIVATED_KEY</h2> <p>The API key has been deactivated, most commonly due to subscription cancelation. To regain access to the API, a <a href="/#get-access">new subscription</a> is required.</p> <h2 id="exceeded-freq-limit"><a href="#exceeded-freq-limit" class="header-anchor">#</a> EXCEEDED_FREQ_LIMIT</h2> <p>The request was rate-limited (HTTP status code 429). Reduce the number of API calls being sent concurrently by spacing out API calls over several seconds. The rate limit is currently 30 API calls per second.</p> <p>There are a couple of reasons that 429s can occur:</p> <ul><li><p>If our system receives a large increase in traffic, it will take some time to scale up, usually in the order of minutes. Whilst this is happening, some requests might be knocked back with 429s.</p></li> <li><p>If requests are sent at a rate close to the limit, some requests can still trigger rate limiting since our servers can receive requests at a different rate to which they are sent. For example, if you send 30 requests per second for 2 seconds, our servers might receive 25 requests in the first second, 33 in the next second (3 of which will be limited), and the remaining 2 requests after that. The rate at which our systems receive the requests will depend on network conditions, which are influenced by many factors outside of our control.</p></li></ul> <p>Both of these scenarios mean that 429s can occur sometimes, and they are more likely if requests are being sent close to the limit.</p> <p>To handle a request that has been rate limited, consider retrying the request after a couple of seconds. Also avoid unnecessary API calls. For example, API calls to the sports or events endpoints can be made infrequently, since the responses don't change often.</p> <h2 id="out-of-usage-credits"><a href="#out-of-usage-credits" class="header-anchor">#</a> OUT_OF_USAGE_CREDITS</h2> <p>The usage credit limit of the subscription has been reached for the month.</p> <p>Usage credits can be monitored by accessing the HTTP response headers, which are returned with every API call:</p> <ul><li><code>x-requests-remaining</code>   The usage credits remaining until the quota resets</li> <li><code>x-requests-used</code>   The usage credits used since the last quota reset</li> <li><code>x-requests-last</code> The usage cost of the last API call</li></ul> <p>Usage can be tracked and subscriptions can be changed in the <a href="/account/">accounts portal</a>. If you have not already done so, you will need to create a new account, even if you have active subscriptions. A new account can be <a href="/account/?initialAuthState=signUp">created here</a>.</p> <h3 id="troubleshooting-unexpected-usage-tracking-usage"><a href="#troubleshooting-unexpected-usage-tracking-usage" class="header-anchor">#</a> Troubleshooting Unexpected Usage &amp; Tracking Usage</h3> <p>Tips for troubleshooting unexpected usage and tracking usage can be found on <a href="/manage/troubleshoot-unexpected-usage.html">this page</a>.</p> <h3 id="upgrading-a-subscription"><a href="#upgrading-a-subscription" class="header-anchor">#</a> Upgrading a Subscription</h3> <p>A paid subscription can be upgraded at any time. Details on how to upgrade and upgrade behavior can be found on <a href="/manage/upgrade-downgrade-cancel-a-subscription.html">this page</a>.</p> <h2 id="missing-region"><a href="#missing-region" class="header-anchor">#</a> MISSING_REGION</h2> <p>The endpoint being called requires a <code>regions</code> query parameter, which specifies regions of bookmakers to be queried, for example <code>&amp;regions=us,uk</code></p> <p>Alternatively the <code>bookmakers</code> parameter can be used, for example <code>&amp;bookmakers=draftkings,pinnacle</code></p> <p>A list of valid bookmakers and regions can be <a href="/sports-odds-data/bookmaker-apis.html">found here</a>.</p> <h2 id="invalid-region"><a href="#invalid-region" class="header-anchor">#</a> INVALID_REGION</h2> <p>One or more of the specified regions is invalid. A list of valid bookmaker regions can be <a href="/sports-odds-data/bookmaker-apis.html">found here</a>.</p> <p>Multiple comma-separated regions can be specified, for example</p> <p><code>https://api.the-odds-api.com/v4/sports/soccer_epl/odds?apiKey=YOUR_API_KEY&amp;markets=h2h&amp;regions=uk,eu</code></p> <h2 id="invalid-bookmakers"><a href="#invalid-bookmakers" class="header-anchor">#</a> INVALID_BOOKMAKERS</h2> <p>The <code>bookmakers</code> parameter can be used as an alternative to the <code>regions</code> parameter. The <code>bookmakers</code> parameter is a comma-separated list of one or more bookmaker keys. A list of bookmaker keys can be <a href="/sports-odds-data/bookmaker-apis.html">found here</a>.</p> <p>Multiple comma-separated bookmaker keys can be specified. Bookmakers can be from any region, for example</p> <p><code>https://api.the-odds-api.com/v4/sports/basketball_nba/odds?apiKey=YOUR_API_KEY&amp;markets=h2h&amp;bookmakers=draftkings,fanduel,pinnacle</code></p> <h2 id="missing-market"><a href="#missing-market" class="header-anchor">#</a> MISSING_MARKET</h2> <p>The endpoint being called requires a <code>markets</code> query parameter, which specifies betting markets to be queried. For most endpoints, this parameter is not required and will default to the <code>h2h</code> market.</p> <h2 id="invalid-market"><a href="#invalid-market" class="header-anchor">#</a> INVALID_MARKET</h2> <p>One or more of the markets being queried are invalid or unsupported by the endpoint being used. A list of valid market keys can be <a href="/sports-odds-data/betting-markets.html">found here</a>.</p> <p>This error is commonly caused when non-featured markets are used with the odds or historical odds endpoints, which only support <a href="/sports-odds-data/betting-markets.html#featured-betting-markets">featured markets</a>.</p> <p><a href="/sports-odds-data/betting-markets.html#additional-markets">Non-featured markets</a>, such as player props, period markets and alternate markets can be queried one event at a time using the <a href="/liveapi/guides/v4/#get-event-odds">event-odds</a> or <a href="/liveapi/guides/v4/#get-historical-event-odds">historical-event-odds</a> endpoints.</p> <p>For example, this will cause an error since player_points is a non-featured market, and the odds endpoint only accepts featured markets:</p> <p><code>https://api.the-odds-api.com/v4/sports/basketball_nba/odds?apiKey=YOUR_API_KEY&amp;regions=us&amp;oddsFormat=american&amp;markets=player_points</code></p> <p>The events-odds endpoint accepts any markets. In this example, b308ed60cbb2d1324946c7289190cc88 was the event id of the Timberwolves @ Nuggets game on 2024-05-04. The event id will need to be replaced with a current event id, which can be obtained from the <a href="/liveapi/guides/v4/#get-events">events</a> endpoint.</p> <p><code>https://api.the-odds-api.com/v4/sports/basketball_nba/events/b308ed60cbb2d1324946c7289190cc88/odds?apiKey=YOUR_API_KEY&amp;regions=us&amp;oddsFormat=american&amp;markets=player_points</code></p> <h2 id="invalid-market-combo"><a href="#invalid-market-combo" class="header-anchor">#</a> INVALID_MARKET_COMBO</h2> <p>This error usually occurs if the sportKey represents an outrights (futures) event, in which case the valid market is <code>outrights</code>.</p> <p>For example this will cause the error:</p> <p><code>https://api.the-odds-api.com/v4/sports/americanfootball_nfl_super_bowl_winner/odds?apiKey=YOUR_API_KEY&amp;regions=us&amp;oddsFormat=american&amp;markets=h2h</code></p> <p>This is a valid combination</p> <p><code>https://api.the-odds-api.com/v4/sports/americanfootball_nfl_super_bowl_winner/odds?apiKey=YOUR_API_KEY&amp;regions=us&amp;oddsFormat=american&amp;markets=outrights</code></p> <h2 id="invalid-date-format"><a href="#invalid-date-format" class="header-anchor">#</a> INVALID_DATE_FORMAT</h2> <p>The specified <code>dateFormat</code> query parameter is invalid. For valid formats, see the &quot;parameters&quot; section for the relevant endpoint in <a href="/liveapi/guides/v4/" class="router-link-active">the docs</a>.</p> <p>The <code>dateFormat</code> parameter is not required for most endpoints, and will default to <code>iso</code> (ISO8601).</p> <h2 id="invalid-odds-format"><a href="#invalid-odds-format" class="header-anchor">#</a> INVALID_ODDS_FORMAT</h2> <p>The specified <code>oddsFormat</code> query parameter is invalid. For valid formats, see the &quot;parameters&quot; section for the relevant endpoint in <a href="/liveapi/guides/v4/" class="router-link-active">the docs</a>.</p> <p>If this parameter is missing, the <code>oddsFormat</code> will default to <code>decimal</code>.</p> <h2 id="invalid-all-sports-param"><a href="#invalid-all-sports-param" class="header-anchor">#</a> INVALID_ALL_SPORTS_PARAM</h2> <p>The <code>all</code> query parameter must be <code>true</code> or <code>false</code>.</p> <p>This will likely be relevant for the <a href="/liveapi/guides/v4/#get-sports">sports endpoint</a>.</p> <h2 id="invalid-sport"><a href="#invalid-sport" class="header-anchor">#</a> INVALID_SPORT</h2> <p>The sport path parameter is missing or invalid. A list of valid sport keys can be <a href="/sports-odds-data/sports-apis.html">found here</a>, or by called the <a href="/liveapi/guides/v4/#get-sports">sports endpoint</a>.</p> <h2 id="unknown-sport"><a href="#unknown-sport" class="header-anchor">#</a> UNKNOWN_SPORT</h2> <p>The specified sport is not found. A list of valid sport keys can be <a href="/sports-odds-data/sports-apis.html">found here</a>, or by called the <a href="/liveapi/guides/v4/#get-sports">sports endpoint</a>.</p> <h2 id="invalid-scores-days-from"><a href="#invalid-scores-days-from" class="header-anchor">#</a> INVALID_SCORES_DAYS_FROM</h2> <p>The <code>daysFrom</code> parameter must be an integer greater than or equal to 1, and less the maximum specified in <a href="/liveapi/guides/v4/#get-scores">the docs</a> (see the &quot;parameters&quot; section of the relevant endpoint).</p> <p>For example</p> <p><code>https://api.the-odds-api.com/v4/sports/baseball_mlb/scores?apiKey=YOUR_API_KEY&amp;daysFrom=2</code></p> <h2 id="invalid-event-ids"><a href="#invalid-event-ids" class="header-anchor">#</a> INVALID_EVENT_IDS</h2> <p>The <code>eventIds</code> query parameter is invalid. For endpoints that return a list of events, this parameter is used to filter the API response to specific events. This parameter must contain comma separated event ids, each of which is 32 characters in length.</p> <p>Depending on the endpoint being queried, event ids can be found by calling the <a href="/liveapi/guides/v4/#get-events">events endpoint</a> or the <a href="/liveapi/guides/v4/#get-historical-events">historical events endpoint</a>.</p> <h2 id="invalid-event-id"><a href="#invalid-event-id" class="header-anchor">#</a> INVALID_EVENT_ID</h2> <p>The event id parameter in the URL path is invalid. The event id must be 32 characters in length.</p> <p>Depending on the endpoint being queried, event ids can be found by calling the <a href="/liveapi/guides/v4/#get-events">events endpoint</a> or the <a href="/liveapi/guides/v4/#get-historical-events">historical events endpoint</a>.</p> <p>For example, c163b5f5f4579c8293266956ccf3d9bd is the event id for Tampa Bay Rays @ Los Angeles Angels on 2024-04-09:</p> <p><code>https://api.the-odds-api.com/v4/historical/sports/baseball_mlb/events/c163b5f5f4579c8293266956ccf3d9bd/odds?apiKey=YOUR_API_KEY&amp;markets=totals_1st_5_innings&amp;regions=us&amp;oddsFormat=american&amp;date=2024-04-08T15:10:00Z</code></p> <h2 id="event-not-found"><a href="#event-not-found" class="header-anchor">#</a> EVENT_NOT_FOUND</h2> <p>The event id specified in the URL path was not found. The most common cause is that the event has concluded. This error can also occur if the event id was not correctly specified.</p> <h2 id="missing-historical-timestamp"><a href="#missing-historical-timestamp" class="header-anchor">#</a> MISSING_HISTORICAL_TIMESTAMP</h2> <p>The <code>date</code> parameter is required when querying historical endpoints. This represents the timestamp of the historical snapshot to be queried. More information can be found for the relevant endpoint in <a href="/liveapi/guides/v4/" class="router-link-active">the docs</a>.</p> <h2 id="invalid-historical-timestamp"><a href="#invalid-historical-timestamp" class="header-anchor">#</a> INVALID_HISTORICAL_TIMESTAMP</h2> <p>The <code>date</code> parameter must be in ISO8601 format, for example:</p> <p><code>https://api.the-odds-api.com/v4/historical/sports/baseball_mlb/odds?apiKey=YOUR_API_KEY&amp;regions=us&amp;markets=h2h,spreads&amp;date=2024-04-30T12:45:00Z</code></p> <h2 id="invalid-commence-time-from"><a href="#invalid-commence-time-from" class="header-anchor">#</a> INVALID_COMMENCE_TIME_FROM</h2> <p>The <code>commenceTimeFrom</code> parameter must be in ISO8601 format, for example <code>2024-04-30T00:00:00Z</code></p> <h2 id="invalid-commence-time-to"><a href="#invalid-commence-time-to" class="header-anchor">#</a> INVALID_COMMENCE_TIME_TO</h2> <p>The <code>commenceTimeTo</code> parameter must be in ISO8601 format, for example <code>2024-04-30T23:59:59Z</code></p> <h2 id="invalid-commence-time-range"><a href="#invalid-commence-time-range" class="header-anchor">#</a> INVALID_COMMENCE_TIME_RANGE</h2> <p>The <code>commenceTimeTo</code> parameter must be later than <code>commenceTimeFrom</code></p> <h2 id="historical-unavailable-on-free-usage-plan"><a href="#historical-unavailable-on-free-usage-plan" class="header-anchor">#</a> HISTORICAL_UNAVAILABLE_ON_FREE_USAGE_PLAN</h2> <p>Historical data is only accessible on <a href="/#get-access">paid usage plans</a>.</p> <p>Sample historical data can be <a href="/historical-odds-data/#sample-historical-odds-data">found here</a>.</p> <h2 id="invalid-participant-id"><a href="#invalid-participant-id" class="header-anchor">#</a> INVALID_PARTICIPANT_ID</h2> <p>The participant id is invalid. It must start with <code>par_</code>, for example <code>par_01hqmkq6fceknv7cwebesgrx03</code></p> <h2 id="invalid-include-links"><a href="#invalid-include-links" class="header-anchor">#</a> INVALID_INCLUDE_LINKS</h2> <p>The <code>includeLinks</code> parameter determines whether links to bookmaker websites will be included in the API response.</p> <p>If <code>includeLinks</code> is provided, it must be either <code>true</code> or <code>false</code>.</p> <p>If <code>includeLinks</code> is not provided, it will default to <code>false</code>.</p> <h2 id="invalid-include-sids"><a href="#invalid-include-sids" class="header-anchor">#</a> INVALID_INCLUDE_SIDS</h2> <p>The <code>includeSids</code> parameter determines whether source ids (sids) will be included in the API response. An example of a sid includes a bookmaker's id for an event, market or betting selection.</p> <p>If <code>includeSids</code> is provided, it must be either <code>true</code> or <code>false</code>.</p> <p>If <code>includeSids</code> is not provided, it will default to <code>false</code>.</p> <h2 id="invalid-include-bet-limits"><a href="#invalid-include-bet-limits" class="header-anchor">#</a> INVALID_INCLUDE_BET_LIMITS</h2> <p>The <code>includeBetLimits</code> parameter determines whether a bookmaker's bet limits will be returned in each betting outcome in the API response.</p> <p>If <code>includeBetLimits</code> is provided, it must be either <code>true</code> or <code>false</code>.</p> <p>If <code>includeBetLimits</code> is not provided, it will default to <code>false</code>.</p> <h2 id="invalid-include-multipliers"><a href="#invalid-include-multipliers" class="header-anchor">#</a> INVALID_INCLUDE_MULTIPLIERS</h2> <p>The <code>includeMultipliers</code> parameter determines whether a betting outcome's multiplier is included in the the API response. This is only applicable to DFS sites (<code>us_dfs</code> region).</p> <p>If <code>includeMultipliers</code> is provided, it must be either <code>true</code> or <code>false</code>.</p> <p>If <code>includeMultipliers</code> is not provided, it will default to <code>false</code>.</p> <h2 id="invalid-include-rotation-numbers"><a href="#invalid-include-rotation-numbers" class="header-anchor">#</a> INVALID_INCLUDE_ROTATION_NUMBERS</h2> <p>The <code>includeRotationNumbers</code> parameter determines whether to include rotation numbers in the API response, if available.</p> <p>If <code>includeRotationNumbers</code> is provided, it must be either <code>true</code> or <code>false</code>.</p> <p>If <code>includeRotationNumbers</code> is not provided, it will default to <code>false</code>.</p> <h2 id="historical-markets-unavailable-at-date"><a href="#historical-markets-unavailable-at-date" class="header-anchor">#</a> HISTORICAL_MARKETS_UNAVAILABLE_AT_DATE</h2> <p>One or more of the requested market keys are not available at the timestamp of the &quot;date&quot; parameter. The specific market keys will be listed in the API's error message response.</p> <h2 id="invalid-status"><a href="#invalid-status" class="header-anchor">#</a> INVALID_STATUS</h2> <p>The <code>status</code> parameter is invalid.
